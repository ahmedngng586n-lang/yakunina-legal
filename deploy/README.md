# Серверный запуск

Приложение работает на Python 3.10+ без сторонних пакетов. На сервере нужен HTTPS-прокси и постоянный каталог SQLite. Секреты не размещаются в Git и в `dist`.

На подготовленном Ubuntu-сервере:

1. Создайте системного пользователя `yakunina` и каталог `/var/lib/yakunina-legal` с владельцем `yakunina:yakunina` и правами `700`.
2. Разместите проверенный выпуск в `/opt/yakunina-legal/releases/ИМЯ_ВЫПУСКА`, направьте `/opt/yakunina-legal/current` на этот каталог.
3. Скопируйте `config.example.json` в `/etc/yakunina-legal/config.json` и заполните секреты. Каталог: `root:yakunina`, `750`; файл: `root:yakunina`, `640`. Пользователь приложения читает секреты, но не изменяет их.
4. Установите `yakunina-legal.service` в `/etc/systemd/system/`, выполните `systemctl daemon-reload` и `systemctl enable --now yakunina-legal`.
5. Получите сертификат для своего домена. Перед изменением nginx сохраните `/etc/nginx`. Подставьте домен и пути сертификата в `nginx.conf`, проверьте `nginx -t`, затем выполните `systemctl reload nginx`.

Проверка: `curl -fsS https://ВАШ_ДОМЕН/api/health`. Статус службы не доказывает доставку уведомлений: отправьте помеченное тестовое обращение и проверьте получение карточки ботом.

Для Pages задайте `apiBaseUrl` в `dist/assets/site-config.js`, добавьте точный origin Pages в `allowed_origins` серверной конфигурации и синхронизируйте `docs`. Без доступного API сайт предлагает прямой звонок или сообщение.

Бот получает обращения только для настроенного получателя. Перед запуском уведомлений получатель должен открыть бота и начать диалог. Статусы заявок и ответы клиенту доступны только авторизованному владельцу. Привязка и позиция Telegram-поллинга хранятся в SQLite.

Резервная копия должна включать закрытый каталог данных, конфигурацию и предыдущий выпуск. Для отката переключите `current` на сохранённый выпуск и перезапустите службу. Не публикуйте резервные копии с обращениями или токеном.
