# Светлана Якунина — сайт и Telegram CRM

Сайт помогает посетителю узнать свою ситуацию, понять формат и начальную цену помощи и оставить короткое обращение. Тема выбранной карточки переносится в форму. После сохранения посетитель видит номер обращения и следующий шаг; статус очереди отличим от подтверждённой передачи уведомления.

## Telegram CRM

Владелец получает отдельные события начала чата, сообщения клиента, заявки и смены этапа. Заявка содержит имя, контакт, тему, описание, начальную цену, источник и номер. Этапы: «Новая», «Связались», «Консультация», «Закрыта». Кнопки изменяют карточку и сохранённый этап; встреча согласуется отдельно.

Чтобы ответить посетителю в чат сайта, используйте Telegram «Ответить» на сообщение клиента. Ответ появляется в его открытом диалоге. Перезагрузка в той же вкладке сохраняет доступ к этому диалогу; закрытие вкладки может его завершить. Для продолжения общения клиент может оставить телефон, Telegram или email в заявке.

Бот закрепляется за владельцем через персональную одноразовую ссылку `/start` либо явно указанный username и фразу подключения. Произвольный первый посетитель не становится получателем. Кнопки и ответы проверяют числовой ID владельца, чат и исходную карточку. Привязка и позиция чтения обновлений сохраняются в SQLite.

Обращения и события сохраняются до отправки. Временный сбой Telegram запускает повтор доставки. Повторная отправка формы с тем же случайным идентификатором не создаёт новую заявку. При потере сетевого подтверждения Telegram может повторить уведомление с тем же номером: это доставка как минимум один раз, а не гарантия единственного сообщения.

## Конфигурация и запуск

Python 3.10+, стандартная библиотека:

```sh
python server/server.py --host 127.0.0.1 --port 9137 --config /secure/legal-config.json
```

Пример закрытых настроек — `deploy/config.example.json`; инструкция Ubuntu/nginx/systemd — `deploy/README.md`. Основные поля: `telegram_token`, `telegram_chat_id` либо `telegram_owner`/`telegram_pairing_code`, `lead_db`, точный список `allowed_origins`. За доверенным локальным nginx задайте `trust_proxy: true`; прямой сервер не должен доверять заголовку IP.

Переменные окружения: `LEGAL_TELEGRAM_TOKEN`, `LEGAL_TELEGRAM_CHAT_ID`, `LEGAL_TELEGRAM_OWNER`, `LEGAL_TELEGRAM_OWNER_ID`, `LEGAL_TELEGRAM_PAIRING_CODE`. AI является отдельной необязательной функцией: `LEGAL_AI_API_KEY`, `LEGAL_AI_BASE_URL`, `LEGAL_AI_MODEL`.

`dist/assets/site-config.js` содержит только публичные настройки. `apiBaseUrl` подключает статическую версию к HTTPS-серверу. Если API недоступен, сайт предлагает прямой звонок или сообщение и не имитирует успешную отправку. В `docs` хранится точная копия `dist` для Pages.

## Данные и API

- `GET /api/health` — доступные функции, состояние доставки.
- `POST /api/lead` — заявка с согласием и случайным `request_id`.
- `POST /api/events` — только согласованное событие `chat_started`; без содержания переписки.
- `POST /api/messages` — сообщение юристу с согласием; первый ответ выдаёт закрытый токен диалога.
- `GET /api/conversation?session_id=...` — история своего диалога; токен передаётся в заголовке `Authorization: Bearer ...`, не в URL.
- `POST /api/chat` — отдельный AI-помощник, если подключён.

Цены определяет сервер. Секреты, SQLite и персональные обращения не размещаются в GitHub, архиве сайта и `dist`. Метрика не получает имя, контакт или текст; при `metrikaId: 0` она отключена. Хранение отправленных обращений и переписки ограничено 30 днями, недоставленная очередь сохраняется для повтора.

## Проверка

```sh
python -m unittest discover -s server -p 'test_*.py' -v
```

Тесты проверяют согласие, серверную цену, повторные запросы, очередь, приватность диалогов и авторизацию владельца. Telegram в автоматических тестах подменён; успешные тесты не доказывают реальное получение уведомлений. Для проверки настоящей доставки нужен начатый диалог с владельцем и отдельное тестовое обращение.

Workflow `checks.yml` проверяет Python, синтаксис JavaScript и совпадение `docs`/`dist`. Ручной `publish.yml` обновляет Pages из текущих исходников; старый архив больше не перезаписывает новые изменения.
